# WP05 purchased cooking sauces: identity and recipe-demand review

- **Reviewed:** 2026-10-10
- **Status:** Proposal only. No canonical catalog, ledger, recipe, plan, roadmap, code, or test file was changed.
- **Scope:** The open WP05 checklist at plan lines 2118–2119: pesto and variants, tapenade, anchovy paste, capers/caperberries, bagna cauda, tomato sauce/passata, béchamel, hollandaise, and other purchased cooking sauces.
- **Recommendation:** Add source-qualified, identity-only references for classical pesto, tapenade, anchovy paste, passata, and bagna cauda. Keep the existing tomato-sauce and marinara references and exact recipe links. Route capers/caperberries to the adjacent pickled-product checklist. Hold béchamel/hollandaise activation until a recipe line distinguishes prepared sauce from dry mix; defer generic “cooking sauce” as too broad.
- **Limits:** No forms, densities, unit mappings, conversions, package yields, or substitutions are proposed. None of the new identity candidates has a bundled recipe line.

## Search collision audit

The proposed IDs `ingredient-ref-pesto`, `ingredient-ref-tapenade`, `ingredient-ref-anchovy-paste`, `ingredient-ref-passata`, and `ingredient-ref-bagna-cauda` are absent from the live references. Their proposed exact names and aliases have no exact normalized-key owner in the live reference/form index. The exact queries `tomato sauce` / `sauce tomate` already return only `ingredient-ref-tomato-sauce`; `marinara sauce` / `sauce marinara` return only `ingredient-ref-marinara-sauce`.

The exception is the held `hollandaise` item: bare `hollandaise` already matches the Dutch-process cocoa reference because its French display/alias includes that word. A full phrase such as `sauce hollandaise` does not currently collide, but the one-word search must be addressed before activation. Tomato-related partial search can continue to show multiple distinct tomato references; this proposal does not collapse those products.

The proposed source-ID prefix `WP05-CSCR-20261010` was checked against all current ledger entries, catalog proposals, and batch documents. IDs `WP05-CSCR-20261010-S01` through `S25` had no collisions at snapshot time.
