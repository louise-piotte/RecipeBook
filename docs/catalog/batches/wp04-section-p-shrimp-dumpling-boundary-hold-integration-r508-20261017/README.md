# WP04 Section P R508 integration — shrimp dumpling boundary hold

**Date:** 2026-10-17  
**Review:** [R508 proposal](../../proposals/wp04-section-p-next-seafood-review-r508-20261017.md)

## Disposition

Keep general `shrimp dumplings / dumplings aux crevettes` unallocated. Current Canadian and Québec product listings support the wording, but activating only a shrimp-specific row would make the broad `dumpling(s)` queries return a misleading singleton. Reviewed products also cover different named styles and fillings, and the bundled recipe corpus contains no demand for this identity.

No reference, form, alias, legacy candidate, ledger record, recipe link, measure, conversion, yield, or substitution was added. Existing shrimp-ball and wrapper identities remain separate. The specific style names and product package amounts remain source-scoped evidence only.

## Evidence and validation

The proposal records the current product sources, the reused OQLF terminology source, exact-key ownership, picker projections, and the full manifest scan (114 recipes / 1,123 ingredient rows; no matching files or rows). It records the source limits and preserves the broad Asian-dumpling meaning of `dumpling` in Québec usage.

The checklist, roadmap, and workflow now point to this hold. This is documentation-only; no software tests, build, emulator check, or deployment was needed. The active database JSON and generated index were not changed.
