# WP04 Section P R118 — bigeye tuna picker hold

## Decision

Keep *Thunnus obesus* outside active references and the research ledger. The qualified names
`bigeye tuna / thon obèse` are supported, but displaying `Bigeye tuna` would make the bare `bigeye`
query return this one species. The current CFIA selector also uses unhyphenated “Bigeye” in names for
other fish taxa. Those examples are illustrative, not an exhaustive list, and those taxa are not
represented in the active picker.

This review adds no reference, alias, form, ledger candidate, measure, recipe link, conversion,
yield, or substitution. The generic tuna reference and recipe 111#1 remain unchanged; the bundled
corpus has no species-specific bigeye tuna demand.

## Evidence and next boundary

CFIA identifies *T. obesus* with Bigeye Tuna; OQLF connects “thon ventru” and “thon obèse” to the
species, and a current Québec supplier uses “THON OBÈSE”. Those qualified names do not resolve the
broader picker collision. The 2017 Canada Gazette table is proposal-era text; current SFCR §262
addresses flesh-colour expressions on sealed tuna labels, not a species-name crosswalk.

See the [R118 proposal](../../proposals/wp04-next-section-p-bigeye-tuna-picker-boundary-review-20261014-r118.md)
for the source register, current picker audit, and measurement and product-state limits. Section P
remains open; revisit the identity if the broader unhyphenated `Bigeye` fish-name group is represented
in the picker.

This was a documentation-only hold. No app, Gradle, instrumentation, or emulator tests were run.
